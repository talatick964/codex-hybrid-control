# Возможности

## Подключения

- Выбор API-модели и уровня рассуждения.
- Профили с отдельным адресом провайдера и наборами моделей.
- Предпросмотр изменений с проверкой того, что профиль не поменялся до применения.
- Резервные копии, контрольные точки и откат.
- Обратимое отключение Hybrid Control до обычного Codex.

## Диагностика и восстановление

- Проверка конфигурации, версии и параметров Codex CLI, каталога моделей и ответов MCP-мостов.
- API-пробы: доступность модели, потоковые ответы, инструменты и изображения.
- Общая проверка и исправление компонентов одной кнопкой.
- Отчёт с удалением известных ключей и чувствительных полей.
- Ограниченное ожидание медленных ответов и зависших дочерних процессов.

## Локальное управление

Режим «Авто» использует UI Automation для доступных элементов Windows и Chrome DevTools Protocol для отдельной сессии Chrome/Edge. Если элемент не поддерживается, остаются снимок экрана и настоящая мышь. Режим «Только мышь» сохраняет обычные клики и ввод.

Разрешения на снимки, ввод и запуск приложений регулируются отдельно. Встроенный просмотр страниц подходит для чтения публичных страниц; отдельная управляемая сессия браузера нужна для взаимодействий с DOM.

Для изменяющих действий используйте стабильный `action_id`. Повтор запроса завершённого действия возвращает его запись без повторного ввода. Неизвестный результат требует проверки окна. После клика или вызова элемента нужно проверить достигнутое состояние.

## API-агенты

`hybridWorkers` запускает внешние API-профили вместо нативных subagents. У воркеров есть статусы, ограничение времени и наблюдение за процессами. Доступность конкретных моделей проверяется у провайдера; имена профилей сами по себе её не гарантируют.

## Известные ограничения

Панель не может исправить все ошибки удалённого API и не управляет внутренними механизмами Codex Desktop. Если сам stdio-хост моста завершается, переподключение выполняет Codex. UIA доступна не во всех приложениях, а браузерный мост управляет отдельной сессией.
