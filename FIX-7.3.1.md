# 7.3.1 — завершение работы и остановка повторов

Добавлены дополнительные проверки поверх шлюза версии 7.3.0.

- Обработчик завершения распознаёт объявления следующего действия, пустой ответ после инструмента, повреждённые служебные теги и незакрытый план. Если модель уже закончила работу, ей предлагается сверить и закрыть план.
- После первой автоматической попытки продолжение разрешается только при новых результатах инструментов. Изменившиеся ID вызовов и время выполнения прогрессом не считаются. Не более шести автоматических продолжений на один ход: бесконечное продолжение само стало бы зацикливанием.
- Шлюз обнаруживает четыре последовательных одинаковых вызова с одинаковыми результатами и останавливает следующий такой вызов до его передачи Codex. Новые параметры, изменившийся результат или новое поручение пользователя снимают этот признак.
- Проверяется завершённость обычных JSON-ответов и корректность аргументов инструментов. Вызовы в потоке сверяются с итоговым ответом; события после завершения не передаются.
- Обновлённый шлюз получает отдельный адрес при обнаружении работающей старой версии. Ошибка запуска откатывает адрес. Старый процесс не уничтожается по непроверенному PID.
- Инструкции для API-режима объясняют ограниченное ожидание команд, проверку готовности серверов и завершение всех согласованных пунктов задачи.

Предел API-запроса — 180 секунд, отсутствия данных — 60 секунд. Сигналы keepalive не отменяют общий предел. Инструменты из оборванного потока не передаются Codex. Сам шлюз не выполняет и не повторяет команды.

## Включение

Запустите `dist/7.3.1/Codex-Hybrid-Control.exe` или `run_control.bat`. Если включён обычный Codex, восстановите Hybrid Control, выберите API и выполните «Проверить и исправить всё». В Codex CLI проверьте `/hooks` и подтвердите обработчик «Hybrid Control: проверка завершения API», если он ещё не доверенный. После обновления команды обработчика Codex может потребовать новое подтверждение. Перезапустите Codex и создайте новый сеанс.

В режиме полного сброса защита отключена вместе с остальными компонентами Hybrid Control. Текущий режим пользователя не переключается при сборке и тестировании.

## Границы защиты

Без локальной модели используются проверяемые признаки, а не предположение о смысле любого ответа. Это не доказательство выполнения произвольного поручения: модель может ошибочно написать убедительный итог, который невозможно распознать по тексту. Вопросы, необходимость подтверждения и ручная отмена учитываются.

Шлюз ограничивает ожидание API, но не произвольную команду, уже выполняемую самим Codex. Для встроенных команд применяются ограничения Codex; для наших мостов — собственные таймауты и журнал действий. Программа не отменяет без разбора длительные сборки или серверы.

Текст API-ответа показывается после проверки целого ответа. Нельзя одновременно передавать частичные вызовы инструментов и гарантировать, что оборвавшийся поток их не запустит.

Регрессионные сценарии проверяются настоящим Codex CLI с локальным тестовым провайдером: несколько продолжений с прогрессом, прекращение повторов без прогресса, цикл инструмента, зависание потока и единичное выполнение инструмента после обрыва. Внешний платный API в этих сценариях не используется.
