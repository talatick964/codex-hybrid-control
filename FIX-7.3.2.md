# 7.3.2 — устойчивость мостов, безопасный откат и ускорение

Исправлены ошибки, найденные при дополнительном прогоне 11 октября 2026 года.

- Запись запроса в заполненный канал MCP теперь учитывает общий срок ответа. Раньше таймер начинался только после записи, поэтому мост мог зависнуть ещё до ожидания ответа.
- Мост сообщает собственный процесс через одноразовый токен. На Windows сохраняется дескриптор проверенного процесса: при сбое завершается сам транспорт, включая случай упакованного EXE. Приложения, запущенные инструментами, продолжают работать. Сбойный запрос автоматически не повторяется.
- Ошибка запуска API-шлюза не отключает независимые MCP-инструменты. Ошибка записи статуса моста не теряет результат инструмента. Повреждённые ответы протокола обрабатываются как сбой соединения.
- Применение настроек, восстановление и переход к обычному Codex используют общую блокировку. Режим повторно проверяется после ожидания. Ошибка сохранения снимка откатывает применение; частичная ошибка отката возвращает исходное применённое состояние.
- Повреждённые настройки шлюза явно обнаруживаются. Общий ремонт сохраняет их точную резервную копию и восстанавливает конфигурацию. Неудачный запуск возвращает прежние настройки.
- Медленная отправка тела запроса имеет общий срок. Служебные keepalive не продлевают ожидание содержательного ответа. Ручная отмена не увеличивает счётчик ошибок провайдера.
- Проверка завершения не принимает старую команду «стоп» из начала длинной истории за новое поручение. Реальный вопрос или запрос подтверждения сохраняются даже при повреждённых служебных тегах.
- Обработчик потока избегает повторного сканирования больших буферов и ненужного перебора повторов текста. Проверены разделители SSE LF, CRLF и CR, включая разделённые байтовые блоки.
- Панели, надписи и кнопки повторно используют готовое изображение при неизменных параметрах. Обновление статуса проверяет только последние 16 записей мостов вместо всей истории.

## Скорость и проверки

Локальный замер `python benchmark_stream.py`: 10 000 событий, 720 083 байта. До исправления — около 4,2 секунды, после — около 0,4 секунды на этом компьютере. Это примерно десятикратное ускорение обработки потока; оно не измеряет скорость модели или сети.

Полный результат проверки и команды повторного запуска — в [RELEASE_STATUS_RU.md](RELEASE_STATUS_RU.md).

## Обновление

Запустите `run_control.bat` или `dist/7.3.2/Codex-Hybrid-Control.exe`. В активном режиме Hybrid Control выполните «Проверить и исправить всё», проверьте доверие обработчика завершения через `/hooks` в Codex CLI, затем перезапустите Codex и создайте новый сеанс. Подтверждение нужно, только если обработчик ещё не доверенный или его команда изменилась.

Текущий режим обычного Codex сохранён. В нём интеграции и контроль API отключены; для использования защиты сначала восстановите Hybrid Control и выберите своё API-подключение.

Сохраняются ограничения версии 7.3.1: ожидание API до 180 секунд, отсутствие содержательных данных до 60 секунд, ограниченные продолжения только при проверяемом прогрессе и проверка целого ответа перед передачей инструментов. Эти проверки не доказывают смысловую завершённость любого поручения и не управляют произвольной командой, которую выполняет сам Codex.
